# AGENTS.md — issue-attachments

This repository stores binary artifacts that GitHub issues link to: sample workbooks,
reproducer files, logs, recordings. It holds no source code and is not tied to any one
project.

## Layout

```
<owner>/<repo>/<issue-number>/     one folder per issue, e.g. gridcraft/2113/
    README.md                      what the files are, their sha256, how to rebuild them
    <files>                        the artifacts themselves
```

Use the lowercase repository name from the issue URL. Create the folder only when an issue
actually needs a file.

## Rules

- **Only artifacts that an issue links to.** No scratch files, no drafts. Every file must be
  referenced from at least one issue or comment, otherwise it is dead weight.
- **No secrets, credentials, tokens or personal data.** Strip real customer data, names,
  addresses and account numbers before committing. Prefer a generated, synthetic reproducer
  over a redacted real file.
- **Prefer reproducible over large.** If a file can be regenerated by a script, commit the
  script next to it (and the seed) and say so in the folder README. Rebuild the artifact only
  when the script alone is not enough for the reporter.
- **Write a README in each issue folder** with: what the files are, the exact sizes, the
  sha256 of each binary, and the command that produces them (if generated).
- **Keep images out unless they are the evidence.** Screenshots belong in the issue as
  GitHub attachments (`user-attachments`); do not commit screenshots of third-party
  software here.
- **Never delete a file an open issue links to.** When an issue is closed and nothing
  references the files any more, they may go, but check the issue thread first.
- Files are public and permanent once pushed: treat every push as irreversible.

## Referencing a file from an issue

Link the repository page for a human, and `raw.githubusercontent.com` when a direct download
is needed:

```
https://github.com/<owner>/issue-attachments/blob/main/<project>/<number>/<file>
https://raw.githubusercontent.com/<owner>/issue-attachments/main/<project>/<number>/<file>
```

The file size limit is 100 MB per file; keep a single artifact under a few tens of megabytes
and prefer compression (`.xlsx`, `.zip`, `.gz`) where it does not change the reproducer.
